# Phase 1.6 — Integration Fixes (close the 4 live-data-flow holes for real)

> **Why:** Phase 1.5 wired the units but the live `_cmd_run` path (`# pragma: no cover`) had 4 integration
> holes the unit suite couldn't catch. An independent review found them. This phase fixes them AND makes
> the live wiring testable, so "the system runs end-to-end" is proven, not asserted. Same workflow:
> subagent-driven, TDD, spec→quality gates (opus reviews), commit + push per task. Repo `midas`, branch
> `build/agent-layer`.

**Root cause + the rule:** integration that lives only inside `# pragma: no cover` is untested. For each
fix, EXTRACT the wiring into a small pure/testable function and unit-test it; only the irreducible
`uvicorn.run` / live-ccxt-fetch stays uncovered.

**The 4 holes:**
1. `_cmd_run` passes no `log` to `run_live` → live runs write no decision log → `/api/decisions` + dashboard feed empty.
2. `magic-agent serve` serves a detached demo `PaperExecutor` → `/api/status` disconnected from the running loop.
3. `build_status` output ≠ the fields the Next.js dashboard reads (`symbol`,`qty`,`pnl`,`realized_pnl`,`open_pnl`) → panels blank.
4. `realized_pnl_today` never updated live → daily-loss kill-switch inert in production.

Cross-process design (F4): `run` and `serve` are separate processes. Share state via FILES under
`.magic_agent/`: the **decision log** (`decisions.jsonl`, the feed source) and a **status snapshot**
(`status.json`, written per candle by `run`, read by `serve`). No DB/IPC — pragmatic for the demo.

## Task F1: `magic-agent run` writes the decision log — opus

**Files:** Modify `src/magic_agent/cli.py`; add tests to `tests/test_cli.py`.

**Change:**
- Add `--log` to the `run` subcommand (default `.magic_agent/decisions.jsonl` — same default as `serve`).
- EXTRACT a testable helper `build_run_kwargs(args, *, executor, gateway, context, feed) -> dict` that
  returns the kwargs passed to `run_live(...)`, INCLUDING `log=AgentLog(args.log)` and the
  `PolicyConfig` built from the flags. `_cmd_run` calls this helper then `run_live(**kwargs)`; only the
  real ccxt feed construction stays `# pragma: no cover`.

**Tests:**
- `build_run_kwargs(args, executor=PaperExecutor(), gateway=<fake>, context=..., feed=<fake>)` returns a
  dict whose `log` is an `AgentLog` pointing at `args.log`, and whose `policy_config` is a non-empty
  `PolicyConfig` (fail-closed). (Use a tmp `--log` path.)
- End-to-end-ish: run `run_live` with that `log` + a fake feed that yields one allowed setup → assert a
  JSON line was appended to the log file (proves the live path writes records the dashboard can read).

**Commit:** `fix(agent): magic-agent run writes the JSONL decision log (live audit + dashboard feed)`.

## Task F2: live `realized_pnl_today` so the kill-switch actually trips — opus

**Files:** Modify `src/magic_agent/live.py`; tests in `tests/test_live.py`.

**Change:** In `run_live`, capture `session_start_available = executor.get_account(mark_price=<first
candle close>).available` once, then EACH iteration compute
`realized_pnl_today = executor.get_account(mark_price=candle.close).available - session_start_available`
and pass it to `on_candle(...)`. (In `PaperExecutor`, `available` == realized cash, so the delta is the
session's realized PnL.) Replace the static `realized_pnl_today` param behavior with this live computation
(keep an override seam only if needed for tests).

**Tests (injected fake executor — no network):**
- a fake executor whose `available` drops by 100 after the first close → on the next candle, `on_candle`
  receives `realized_pnl_today == -100`; with a `PolicyConfig(max_daily_loss=50)` the entry is denied
  (`SKIPPED_POLICY`, stays FLAT). Proves the kill-switch trips LIVE off realized losses.
- no loss → `realized_pnl_today == 0.0`, entries proceed.

**Commit:** `fix(agent): track realized_pnl_today in run_live (daily-loss kill-switch live)`.

## Task F3: `build_status` matches the dashboard contract — opus

**Files:** Modify `src/magic_agent/status.py`; tests in `tests/test_status.py`; update callers
(`cli.py` serve provider, F4 snapshot writer) to pass the new args.

**Change:** Extend `build_status(executor, *, symbol, mode, venue, mark_price, starting_equity,
halted=False) -> dict` so the output includes the fields `web/app/page.tsx` reads:
- top-level: add `realized_pnl = account.available - starting_equity`, `open_pnl = account.equity -
  account.available`. (Keep existing keys.)
- each position entry: add `symbol` (the traded symbol), `qty` (= size), `pnl` (the position's unrealized
  = `sign*(mark_price - entry_price)*size`). (Keep `side`/`size`/`entry_price`/`stop_loss`/`take_profit`.)

**Tests:**
- flat → `realized_pnl`/`open_pnl` present (0.0 when nothing happened), `positions == []`.
- open long after a price move → position entry has `symbol`, `qty`, and `pnl` matching `sign*(mark-entry)*size`;
  top-level `open_pnl` equals that unrealized; `realized_pnl == available - starting_equity`.
- still JSON-able.

**Commit:** `fix(agent): build_status emits the dashboard contract (symbol/qty/pnl/realized_pnl/open_pnl)`.

## Task F4: shared live status — `run` writes a snapshot, `serve` reads it — opus

**Files:** Create `src/magic_agent/status_store.py` (or add to `status.py`); modify `src/magic_agent/live.py`
(write snapshot per candle) + `src/magic_agent/cli.py` (serve reads the snapshot); tests in
`tests/test_status_store.py` + `tests/test_cli.py`.

**Change:**
- `write_status_snapshot(path, status: dict) -> None` (atomic-ish: write temp + replace) and
  `read_status_snapshot(path) -> dict | None` (None if absent/unreadable).
- `run_live` writes a fresh `build_status(...)` snapshot to `.magic_agent/status.json` each iteration
  (inject the snapshot path + symbol/mode/venue/starting_equity; the writer call is testable with a tmp path).
- `build_serve_app`'s default `status_provider` READS `.magic_agent/status.json` via
  `read_status_snapshot`, returning it when present, else a clearly-labelled demo fallback. So `serve`
  reflects the live `run` process's latest snapshot.

**Tests:**
- write a dict via `write_status_snapshot` → `read_status_snapshot` returns it; absent file → `None`.
- `build_serve_app(log_path=..., snapshot_path=<tmp with a seeded snapshot>)` → `/api/status` (TestClient)
  returns the seeded snapshot (NOT the demo executor). Absent snapshot → the demo fallback.
- `run_live` (fake feed) writes a snapshot file after processing a candle.

**Commit:** `fix(agent): shared live status snapshot (run writes, serve reads)`.
