# Phase 1.5 — Live Driver (wire the 5 deferred gaps into a runnable loop)

> **Context:** The 18-task plan delivered fully-tested UNITS (64 tests green) but deliberately left the
> live driver unwired. The whole-branch review pinned 5 gaps. This phase strings the units into a
> running end-to-end loop. Same workflow: subagent-driven, TDD where testable, spec→quality gates
> (reviews on opus), commit + push per task. Repo: `midas`, branch `build/agent-layer`.

**The 5 gaps → 4 tasks (+1 optional):**
1. `_cmd_run` is a stub (no poll loop) → **L3**
2. No ASGI entry / nothing serves the API → **L4**
3. LLM advisor not wired (`clamp_advice` tested-but-unused) → **L2** (seam) + **L5** (real advisor, optional)
4. `policy_config` never passed in a live path → **L3**
5. `status_fn` never enriched (dashboard panels render dashes) → **L1**

Architecture rule (unchanged): scanner = sole signal; AI bounded to size-down/wait via `clamp_advice`;
fail-closed `run_policies` is the only path to funds; `scanner_gateway` is the sole `magic_scanner.*`
seam. The live driver must PRESERVE these — it only wires existing units together.

Implementer code is written via TDD against the behavioral spec below (integration code, so the spec is
behavioral + interface-level, not byte-exact). Inherently un-unit-testable bits (uvicorn.run, live ccxt
fetch) are thin `# pragma: no cover` wiring.

## Task L1: Live status provider (`status.py`) — sonnet

**Files:** Create `src/magic_agent/status.py`, `tests/test_status.py`.

**Interface:** `build_status(executor, *, mode: str, venue: str, mark_price: float, halted: bool = False) -> dict`.

**Behavior:** Read `executor.get_position()` + `executor.get_account(mark_price=mark_price)` and return a
JSON-able dict the dashboard (`web/app/page.tsx`) and `/api/status` expect:
```
{"mode", "venue", "halted", "equity", "available", "currency",
 "positions": [ {"side", "size", "entry_price", "stop_loss", "take_profit"} ]  # empty list when flat
}
```
Pure (no network). Side enum → its `.value` string for JSON.

**Tests (TDD, with PaperExecutor):**
- flat executor → `positions == []`, `halted` reflects the arg, equity/available from the account.
- after an open long → one position entry with side "long"/size/entry_price.
- the dict is `json.dumps`-able.

**Commit:** `feat(agent): live status provider for /api/status + dashboard`.

## Task L2: Advisor seam + clamp + baseline logging in the runner (`runner.py`) — opus

**Files:** Modify `src/magic_agent/runner.py` (extend `on_candle`); append tests to `tests/test_runner.py`.

**Change:** Add an optional param to `on_candle`:
`advisor: Callable[[Setup, ContextSnapshot], LlmAdvice | None] = None`.
After `decision = build_decision(...)` (the deterministic baseline) and BEFORE the policy gate / execute:
- capture `baseline_qty = decision.intent.qty if decision.intent else None`.
- if `advisor is not None`: `advice = advisor(setup, ctx)`; if `advice is not None`:
  `decision = clamp_advice(decision, advice)` and capture `llm_size_factor = advice.size_factor`,
  `llm_action_hint = advice.action_hint`.
- the policy gate + `open_position` operate on the (possibly clamped) `decision`.
- the `log` call passes `baseline_qty`, `llm_size_factor`, `llm_action_hint` into `decision_record(...)`.

**Invariants (correctness-critical — the reviewer must confirm):**
- `advisor=None` → byte-identical behavior to today (all existing runner tests pass unchanged; baseline/llm
  log fields are `None`). Backward-compatible.
- The advisor can ONLY reach the decision THROUGH `clamp_advice` — it can never widen authority (the clamp
  already guarantees size-down/wait only; the advisor's raw output is never applied directly).
- Stops-first ordering, the in-position guard, and the policy gate are untouched in placement.

**Tests (append):**
- an advisor returning `LlmAdvice("take", size_factor=0.5)` → opened qty is half the baseline; the log
  record (use a capturing fake log) has `baseline_qty` set and `llm_size_factor == 0.5`.
- an advisor returning `LlmAdvice("wait", ...)` → no position opened (HOLD).
- `advisor=None` → unchanged (one of the existing tests already covers the deterministic path).

**Commit:** `feat(agent): wire optional LLM advisor through clamp_advice in the runner (baseline logging)`.

## Task L3: Live poll loop (`live.py`) + wire into `_cmd_run` — opus

**Files:** Create `src/magic_agent/live.py`, `tests/test_live.py`; modify `src/magic_agent/cli.py` (`_cmd_run`).

**Interface:**
`run_live(executor, *, gateway, context, feed, symbol, policy_config, advisor=None, log=None, now_fn=None, max_iters=None) -> int` (returns the number of candles processed).

**Behavior (the new-closed-candle gate — mirror llm-trading-bot):**
- Loop: call `feed(symbol)` → returns `(candle: Candle, ts)` for the latest CLOSED bar of the execution TF
  (the feed is responsible for dropping the forming bar). Dedupe: skip when `ts <= last_ts`.
- On a new closed candle: `setup_fn = lambda: gateway.scan(symbol)`; call
  `on_candle(executor, setup_fn=setup_fn, context=context, candle=candle, policy_config=policy_config,
  advisor=advisor, log=log, now=<ts or now_fn()>)`.
- `feed` is INJECTED (a fake in tests yielding a fixed list of `(candle, ts)`); `max_iters` bounds the loop
  for tests; the live `feed` (ccxt / scanner feed, drop-forming-bar + closed-bar) is built in `_cmd_run` as
  thin `# pragma: no cover` wiring.

**`_cmd_run` change:** replace the "agent ready" stub tail with: build a real `feed` (closed-bar OHLCV for
`args.symbol`), a `PolicyConfig` from CLI flags (see below), then `run_live(...)`. Keep `paper` default.

**CLI flags to add to `run`:** `--max-daily-loss` (float, default e.g. 50.0), `--max-leverage` (float,
default 5.0), `--require-stop` (flag, default true), `--cooldown-seconds` (float, optional) → assembled
into a non-empty `PolicyConfig` so the live path is fail-closed (run_policies raises on empty). This closes
gap #4.

**Tests (TDD, injected fake feed — no network):**
- a fake `feed` yielding 3 candles with increasing ts → `run_live(..., max_iters=3)` calls `on_candle` 3
  times (assert via a spy executor / capturing log); returns 3.
- a duplicate ts (`ts <= last_ts`) is skipped (not processed twice).
- the `policy_config` passed in is forwarded to `on_candle` (a denying config → no open / `SKIPPED_POLICY`
  logged).

**Commit:** `feat(agent): live poll loop (new-candle gate) wired into magic-agent run with PolicyConfig`.
