# Phase 1.7 — Trust-surface / status-contract completion

> **Why:** An independent review found that 3 dashboard trust signals are dead/placeholder because the
> live status writer doesn't supply them — the same UI↔backend contract-mismatch class as Phase 1.6,
> missed because reviews checked the F3 *subset* of fields, not the *full* set `page.tsx` reads.
> Fix the gaps AND add a contract test so this class can't recur. Same workflow: subagent-driven, TDD,
> spec→quality gates (opus), commit + push per task. Repo `midas`, branch `build/agent-layer`.

**The gaps (all verified in code):**
1. `run_live` writes `build_status(..., halted=False)` — hardcoded. The kill-switch is per-decision
   (`run_policies` daily-loss denial), so the dashboard pill reads "Armed" / "Next trade allowed" while
   the policy engine is actively halting entries. The safety headline is non-functional.
2. `build_status` omits `daily_loss`, `max_daily_loss`, `agent_id` — but `page.tsx` reads all three →
   the daily-loss meter permanently shows "No loss limit reported" and the ERC-8004 badge is always the
   placeholder `0xMIDAS…8004`. `Erc8004Identity` is a tested unit but never wired into the live path.
3. No test pins the UI↔status contract, so this drift passed green unit suites.

## Task P1.7-1: Complete the live status contract (halt + daily-loss + identity) — opus

**Files:** Modify `src/magic_agent/status.py` (`build_status`), `src/magic_agent/live.py` (`run_live`),
`src/magic_agent/cli.py` (`_cmd_run` identity wiring), `web/app/page.tsx` (identity honesty); tests in
`tests/test_status.py`, `tests/test_live.py`.

**Changes:**
- `build_status(...)` gains params + emits: `daily_loss: float | None`, `max_daily_loss: float | None`,
  `agent_id: str | None`. (`halted` already a param — keep.) JSON-able, keep all existing keys.
- `run_live(...)` computes the REAL safety state each candle and writes it into the snapshot via
  `build_status`:
  - `max_daily_loss = policy_config.max_daily_loss` (or None),
  - `daily_loss = max(0.0, -realized_pnl_today)` (loss magnitude; 0 when in profit),
  - `halted = (max_daily_loss is not None and realized_pnl_today <= -abs(max_daily_loss))` — i.e. the
    daily-loss kill-switch is tripping. Pass these (+ the agent_id, see below) into `build_status`.
  - add an optional `agent_id: str | None = None` param to `run_live`, forwarded to `build_status`.
- `_cmd_run` (`# pragma: no cover` wiring): construct `Erc8004Identity(...)`, attempt registration when
  configured (env/registrar; the on-chain call stays pragma-no-cover), and pass the resulting
  `agent_id` (or None) into `run_live`. When unregistered, agent_id is None.
- `web/app/page.tsx`: when `status.agent_id` is absent, the ERC-8004 badge must read an HONEST
  "unregistered" (not the fake `0xMIDAS…8004`); when present, show the real (shortened) id. Read-only,
  no other behavior change.

**Tests (no network — injected fakes):**
- `build_status(...)` emits `daily_loss`/`max_daily_loss`/`agent_id` with the passed values; JSON-able.
- `run_live` with a fake executor whose `available` drops past the cap → the written snapshot has
  `halted == True` and `daily_loss > 0` and `max_daily_loss == <cap>`; a no-loss run → `halted False`,
  `daily_loss 0.0`.
- `run_live` forwards a given `agent_id` into the snapshot.

**Commit:** `fix(agent): live status emits real halted/daily_loss/max_daily_loss + wired agent_id`.

## Task P1.7-2: UI↔status contract test (drift guard) — opus

**Files:** Create `tests/test_ui_status_contract.py`.

**Goal:** A test that PARSES `web/app/page.tsx`, extracts every `status` field the UI reads
(`status?.X`, `status.X`, `status["X"]`), and asserts `build_status(...)`'s output dict emits each —
so a future field the UI reads but the backend doesn't emit FAILS the suite automatically.

**Approach:**
- Read `web/app/page.tsx` as text; regex-extract field names from `status?.<id>` / `status.<id>` /
  `status["<id>"]` accesses (the `StatusData` typed object). Build the read-set.
- Build the emit-set from a representative `build_status(...)` call's keys (status + flatten the keys
  the UI reads off `positions[i]` too — `symbol/side/qty/entry_price/stop_loss/take_profit/pnl`).
- Assert `read_set ⊆ emit_set`, EXCEPT a small explicit `UI_DERIVED_OR_OPTIONAL` allowlist for fields
  that are intentionally UI-internal/derived (document each with a reason). If a field is in neither
  the emit-set nor the allowlist → FAIL with a clear message naming the missing field.
- Also assert the inverse direction is NOT required (backend may emit extra fields).

**This test must FAIL on the pre-P1.7-1 contract** (prove it bites) — i.e. if you remove the P1.7-1
fields it goes red. Note that in the report.

**Commit:** `test(agent): UI↔status contract guard (page.tsx reads ⊆ build_status emits)`.
